# 仓储拣选设计实验室

这是已实现并实际运行、联调的本地中文交互系统。五个页面接入正式 Parquet、原 KnowledgeService 与已保存的布局评价；不执行搜索或全量重新计算。现已增量接入真实语义检索与 DeepSeek 证据助手；本阶段启动、预算与评测以 `../仓储证据助手/README.md` 为准，使用8766入口，原8765进程保留。

## 启动和停止

本机已验证：Windows、Python 3.14.4、DuckDB 2.0.0、rdflib 7.6.0；浏览器用 Codex 内置 Chromium 实际验收。前端原生 ES Modules / SVG，无 Node 构建步骤、CDN、在线字体或运行时网络依赖。

在 PowerShell 中：

```powershell
Set-Location -LiteralPath 'F:\grade3\设计大数据基础\仓储交互系统'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

也可双击 `start.cmd`。访问 <http://127.0.0.1:8765/>。后台隐藏窗口运行，PID 与端口记录在 `server.pid`，日志是 `server.log` 与 `server-error.log`。

停止仅终止本项目记录且经健康接口确认的 PID：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop.ps1
```

前台运行也可用 `python -B .\backend\server.py --port 8765`，以 Ctrl+C 停止。首次启动计算只读输入的完整性哈希，可能需要数秒。第一次加载知识服务也需要数秒；页面有加载提示。

## 数据与依赖

`config/paths.json` 的 `workspace` 相对本成果目录，默认 `..`。该目录下须保留四个上游成果的原有文件夹结构。应用直接复用两个上游 `vendor` 的现有依赖，不写这些目录。`sys.dont_write_bytecode=True` 与 `python -B` 避免产生上游 __pycache__。

如迁移到新电脑，使用相同 Python ABI 与上游 requirements 恢复只读依赖，或将 DuckDB、rdflib 及知识服务间接依赖安装到本应用的 `vendor`（见 `requirements.txt`）。可执行 `python -m pip install --target vendor -r requirements.txt` 安装应用本地依赖。修改路径配置后重启。不要把 CSV 浏览样例替换到正式数据入口。

应用只监听 127.0.0.1；无部署、发布或数据上传。端口占用时使用 `scripts/start.ps1 -Port 8766`，然后访问对应端口。`config/paths.json` 的 port 决定默认端口；测试脚本默认 8765。

## 常见故障

- 启动脚本显示解析错误：脚本已保存 UTF-8 BOM 以兼容 Windows PowerShell 5.1；复制时保留编码。
- 页面提示无法读取数据：确认服务运行，检查 `server-error.log`，再点击重试。缺评价组合属于正常状态，不是服务错误。
- 缺少 `_duckdb` / DLL：上游 vendor 与 Python 版本不兼容；用匹配ABI依赖或应用本地 vendor，不能修改上游包。
- 冻结候选没有 test / R03 / R04：以真实支持组合为准；界面不借数、不自动搜索新方案。
- 移动清单表格需要横向滚动：长ID与详细依据使用表格内部滚动，页面本身不横向溢出。

## 范围和限制

FILI 是有条件单次筛查，正式 LI 全空；时间模型未验证，吞吐和积压改善未评估。只有一个实际主实验 replicate。预算为移动SKU数，不是人民币报价。知识措施保持原状态；新布局模拟不等同于现场验证。

路线选择器列出当前原始过滤前50个批次，事件每页50条；完整统计始终来自全部匹配数据。方案配对默认显示所选SKU在当前划分中按 lift_key 排序的首个真实配对事件，接口也可精确传 lift_key。小屏保留阅读和基本操作，地图细节宜在桌面使用；触屏手势、NVDA/VoiceOver、其他浏览器未做完整专项认证。
